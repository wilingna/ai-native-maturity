# 诚实指标：别再只报"采纳率"了

> 成熟度模型告诉你"在哪一级"。这四个数告诉你"是不是真的在往上走"。
> 它们不进最短板计算，但每次复测前都该拿出来——**自评可以虚高，这四个数很难。**

---

## 为什么采纳率会骗人

"80% 的员工用过 AI"这种数字，在管理层看板上很好看，但说明不了任何事。

2026 年的几份大样本调研呈现的是同一个剪刀差：绝大多数人说 AI 提升了**个人**效率，但能说出 AI 对**公司利润**有正贡献的，只有三分之一多一点；真正拿到显著财务回报的，只是很小一撮。个人在用 ≠ 组织在赚。

所以要换一套更难被"做好看"的指标。

---

## 指标 1 · HITL 率（Human-In-The-Loop，人在回路中 · 人工介入率）

**定义**：agent 的产出里，有多大比例必须由人复核、改动或推翻。

**为什么诚实**：同样是"用起来了"——

| | 采纳率 | HITL 率 | 实际状态 |
|---|---|---|---|
| A 部门 | 40% | 8% | agent 真在干活 |
| B 部门 | 12% | 61% | 人在给 agent 收尾 |

这是完全不同的两种成熟度，采纳率看不出来。

**好处**：它会随时间下降，是天然的进步曲线。"简历筛选节点的人工推翻率从 40% 降到 12%"，比任何"效率提升 X%"的口径都更难被质疑。

**注意**：HITL 率不是越低越好。高风险节点（薪酬、录用、对外承诺）就该保持高 HITL——拿到真回报的公司，恰恰**更**可能事先定义好"什么情况下 AI 产出必须过人"。目标是"该过人的过人、不该过的不过"，而不是把它压到零。

---

## 指标 2 · 返工税

**定义**：AI 省下的时间里，有多少又花在核对、修改、重写 AI 产出上。

**为什么重要**：有大样本调研估算，AI 省下的时间里接近四成被返工吃掉；而且最受返工之苦的，恰恰是被认为最会用技术的年轻员工。

**怎么测**：不需要精确。抽一周、抽一个团队，让大家在日志里标一下"这条 AI 产出我花了多久去改"即可。

**怎么用**：返工税高，通常不是工具不好，而是**不会委派、不会验收**——这指向人才维度的"写 spec"能力，或知识维度的上下文不足。

---

## 指标 3 · 节省时间的去向

**定义**：省下来的时间，最后去了哪——再投入到能力和更高价值的工作，还是直接变成了更多工作量？

**为什么重要**：同一份调研里，把节省时间默默变成加活的公司不在少数；而从 AI 拿到正向结果的员工，更多是把时间用在了深度分析、决策和能力提升上。

**怎么测**：一个问题就够——"过去一个月 AI 帮你省下的时间，你主要用来干什么了？"选项：更多同类工作 / 更难的工作 / 学习 / 不知道。

**怎么用**：如果大多数人选"更多同类工作"，激励维度大概率被高估了。员工不傻——省下时间换来加活，下一次他就不会再告诉你他省了时间。

---

## 指标 4 · 价值口径

**定义**：AI 的价值有没有进入 P&L 或正式的业务 KPI，而不只是停在"效率提升 X%"。

**为什么重要**：走得最远的那批公司，几乎都用 P&L 或业务 KPI 衡量 AI；直接记进经营账的，拿到的价值也明显更高。

**怎么用**：如果一号位维度自评 L4，但说不出 AI 在哪一行财务数字上留下了痕迹——回去改成 L3。

## 附：流程事件日志模板（只追加，不修改）

上面四个数，原料都来自同一张表。一张共享表格就能起步，不必等系统。

| 字段 | 说明 |
|---|---|
| 流程实例 ID | 一件事一条主线（比如一个岗位、一个候选人、一份合同） |
| 节点 | 流程中的哪一步 |
| 时间 | |
| 输入摘要 | 喂给 AI 的关键信息 |
| AI 输出 | 建议 / 评分 / 理由 |
| 人的动作 | 采纳 / 改了 / 推翻 |
| 改了什么 | ⭐ 整张表最有价值的一列 |
| 返工耗时（选填） | 改这一条花了多久 |

**规则只有一条：只追加，不修改。**

这一张表同时给你：
1. **HITL 率与返工税**的真实数据；
2. **审计轨迹**——出了问题能回溯每一步，合规场景尤其需要；
3. **断点恢复能力**——状态在日志里，不在某个 agent 的内存里；
4. **改进方向**——人反复在同一个地方改同一类东西，那就是 agent 该改的地方；
5. **可搬走**——日志是数据不是代码，换平台、换模型都还是你的。
