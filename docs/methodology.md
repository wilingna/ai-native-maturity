# 六阶段：从 L1 到 L5 的落地方法论（v3）

> 成熟度模型回答「你在哪」，这份方法论回答「下一步往哪走」。
> The maturity model tells you *where you are*. This playbook tells you *where to go next*.
>
> 用法：先用[自测工具](https://wilingna.github.io/ai-native-maturity/)定位你的工作基质、真实水位和**最短板**，
> 然后从对应阶段切入——**永远先补最短板，而不是堆最强项。**

---

## 这套方法论的六条底层原则

1. **取最低维定级。** AI 落地是连环锁，整盘卡在最弱的一环。别被漂亮的平均分骗了。
2. **组织视角，不是技术视角。** 卡住企业的，几乎从来不是模型不够强，而是知识没沉淀、权限太乱、员工不愿配合。2026 年的多份大样本研究给出了同一个结论：拉开差距的是工作有没有被重新设计、组织有没有被重新搭，而不是谁买到了更好的模型。
3. **先证明，再扩张。** 每个阶段都以「拿到一个可验证的战果」为过关线，而不是「上了一个工具」。
4. **先定位基质，再谈落点。** 同样一个 agent，放对地方是标配，放错地方是摆设。见第 0 步。
5. **只测正在发生的事。** 不测计划、不测 PPT。自评 L3 及以上必须拿得出证据（自测工具里的"证据闸门"）。
6. **先装刹车，再给自主权。** agent 的自主程度，永远不超过你的控制能力。治理不是创新的对立面——有好刹车的车才敢开快。

---

## 阶段地图

```
⓪ 定位     ① 定向       ② 打捞       ③ 重构       ④ 放大       ⑤ 激励       ⑥ 治理
工作基质 →  一号位对齐 →  知识结构化 →  流程重设计 →  多场景复制 →  机制重设  →  控制先于自主
(不打分)   (破 L1)      (破"空中楼阁") (破 L2→L3)   (上 L4)      (常见最短板)  (上 L5)
```

> 这不是严格的先后顺序，而是**按你的最短板取用**。多数组织真正卡住的是 ③ 流程、⑤ 激励、② 知识这三处。
> ⓪ 和 ⑥ 例外：⓪ 永远先做；⑥ 里的"致命三要素"检查，**第一个 agent 上线前**就该做。

---

## ⓪ 定位 — 你的工作基质在哪（不打分）

**要解决的卡点：** 六个维度分数不低，但落地就是推不动——很可能 agent 被装在了一个正确但空无一人的地方。

几乎所有主流 AI 落地方法论都有一个没说出口的默认前提：**工作发生在群聊里**。这个前提在硅谷成立，在大量中国大型组织里不成立。

**四种基质：** IM（群聊型）· **会议（会议型）** · 文档（文档型）· 系统（流程型）

**判断方法：** 上周最重要的那个决定是在哪里做出的？找三个月前的来龙去脉你会去翻什么？——指向哪儿，哪儿就是你的主基质。

**为什么先做这一步**
基质决定两件事：agent 该嵌在哪，以及"让人看着它干活"该在哪个场合发生。答错这一题，后面六个阶段都会打折。

👉 展开：[`work-substrate.md`](./work-substrate.md)

---

## ① 定向 — 让一号位说出那一句话，并且收拢资源

**要解决的卡点：** 老板嘴上支持、自己从不打开（一号位维度 L2 封顶）；或者 AI 项目散在各部门、各自为战。

**做什么**
- 逼出一句话的 AI 目标：「我们要拿 AI 干什么」——具体到一个业务结果，不是"提效降本"这种空话。
- 让一号位有**可见的亲自动作**：自己用、公开点名、把 AI 纳入一次真实决策。
- **收拢**：只挑 3–4 条对公司经济账最要紧的工作流，做成一个跨年度的统一项目，而不是几十个零散试点。
- 从第一天就定好**价值口径**：AI 的成果最终要能落到 P&L 或业务 KPI 上，而不只是"效率提升 X%"。

**为什么**
组织会模仿一号位真实在做的事，而不是他说的话。经理当众使用 AI，对团队信任度的拉动是实打实的。另外，BCG 2026 年的数据里，最成熟的那批公司把 AI 资金集中成一个多年期项目的比例，是落后者的三倍多；而把 AI 价值直接放进 P&L 追踪的公司，拿到的价值约是不正式衡量者的三倍。

**过关线**
能写下一句话目标 + 一号位近一个月有 ≥3 次可见的"亲自用/公开点名"动作 + 一张不超过 4 条的优先流程清单。

---

## ② 打捞 — 把经验从老员工脑子里捞出来

**要解决的卡点：** 核心 know-how 全散在个人脑子和聊天记录里，AI 调不到（知识维度 L1–L2）。

**做什么**
- 选 1 个高频高价值场景，把"老法师"脑子里的隐性经验，结构化成 AI 能读的上下文。
- 建一个**单一信息源**起步，而不是一上来铺全公司知识库。
- 往 L4 走时，目标从"人能查"升级为"**agent 能读能调**"：知识、数据、技能（Skill）都要有清晰结构、有人维护、有权限边界。
- 把**人工修正**接回来：人在哪里改了 AI 的产出、为什么改——这本身就是最值钱的知识，要回流进知识源。

**为什么**
知识没打捞过，后面流程、Agent 做得再花也是空中楼阁——这是最容易被跳过、又最致命的一步。

**过关线**
至少 1 个关键场景的核心知识被结构化沉淀、有明确维护人，AI 调用后产出可用。

> 💡 这一步的"怎么捞、捞成什么结构、用什么模板"，是落地层的核心交付。

---

## ③ 重构 — 重新设计一条真流程

**要解决的卡点：** 有人偶尔用 AI 干一次（玩具），或者 AI 被贴在旧流程上当搜索框（流程维度 L2→L3 分水岭）。

**做什么**
- 选 1 条端到端业务流程，**先定义要的结果，再决定人和 agent 怎么分工**——而不是在旧流程的某一步插一个 AI。
- 有意识地给每一段选协作方式，不要一味追求"越自主越好"：

  | 方式 | 人的角色 | 适合 |
  |---|---|---|
  | 问答 | 提问、取用 | 查资料、改一句话 |
  | 探索 | 试边界 | 新场景、新工具的摸底 |
  | 委派 | 定方向、验收 | 目标清楚、标准可定义的活 |
  | 协作 | 多轮共创 | 每一步结果决定下一步问题的活 |

- 明确"谁对结果负责"，写进 SOP。
- 从第一天起记 **HITL 率**（见 [`honest-metrics.md`](./honest-metrics.md)）。

**为什么**
干一次叫玩具，进了 SOP 才算上一级。麦肯锡 2026 年的调研里，真正把 AI 变成利润的那一小撮公司，绝大多数都从根上重新设计了工作流，而其他公司做到这一点的只有约四分之一——这是全份报告里最干净的信号。

**过关线**
≥1 条 AI 重设计的流程在真实业务跑，有 before/after 数字，并开始记录 HITL 率。

---

## ④ 放大 — 从一条流程到多场景

**要解决的卡点：** 单点跑通了，但复制不动、依赖少数高手；或者人人都在用，省下的时间却被返工吃掉。

**做什么**
- 把跑通的那条流程，沉淀成"别人照着能抄"的可复制模式。
- 培养一线普通员工也能用，开始出现"一人编排多 Agent"的 **agent 管理者**。
- 开始做**人机编制规划**：哪些岗位该存在、每个岗位里哪些任务交给 agent、需要多少人来监督和验收。

**过关线**
≥2 个核心维度进入 L3 可复制状态，整体不再卡在 L1。

> 💡 **别再教"提示词技巧"了。**
> 跟 agent 一起工作，更像是在流程里管理一个人，而不是问一个问题拿一个回答——**给 agent 写指令，更接近于写规格说明（spec），而不是提问。**
>
> | | 提问 | 写 spec |
> |---|---|---|
> | 心态 | 我不知道，你告诉我 | 我知道要什么，你去做 |
> | 边界 | 隐含、模糊 | 必须显式说明 |
> | 完成标准 | 我看了觉得还行 | 事先定义好什么叫做完 |
> | 失败归因 | AI 答得不好 | **我 spec 写得不清楚** |
>
> 最后一行是关键：只有第二种心智模型会带来能力增长。
> 所以真正该培训的不是 prompt 技巧，是**管理技能**——拆解模糊目标、事先定义验收标准、设检查点、诊断问题出在指令还是能力。
> 这也是为什么 Workday 2026 年的调研发现，相当一部分 AI 省下的时间被返工吃掉了：问题往往不在工具，而在"不会委派、不会验收"。
>
> **推论：组织里最快掌握 agent 协作的，往往不是技术最好的人，是带过团队、会拆活、会验收的人。** 识别这批人，是选"种子用户"最省力的方法。

> ⚠️ **认知公地的悲剧：别让 AI 吃掉学徒期。**
> 能审核 AI 产出的人，是从"亲手做过大量入门活"里长出来的。如果入门级的活全交给 agent，三五年后组织里就没有人有能力判断 agent 做得对不对了。
> L4 以上的组织要刻意保留**新人成长为专家的路径**：让新人在 agent 旁边做验收、做例外处理、做复盘，而不是被直接跳过。

## ⑤ 激励 — 重设机制，让员工愿意配合

**要解决的卡点：** 员工觉得配合 AI 是"给自己挖坟墓"，或者偷偷用不敢说（激励维度，最常见的隐藏最短板）。

**做什么**
- 在考核权重里，给"**用 AI 重构自己的工作**"和"**贡献组织资产**（Skill / Cases / 知识）"留出位置。
- **奖励尝试，哪怕早期结果不稳。** 微软 2026 年的调研里，多数 AI 用户怕掉队，但只有很少一部分人说自己在"结果还不稳定时尝试重构工作"会被认可——这个落差就是激励维度要补的洞。
- 管好**省下的时间去哪**：有计划地再投入到能力建设，而不是直接变成加活。省下的时间被默默变成更多工作量，是员工"消极配合"的头号原因。
- 让早期贡献者尝到甜头——可见的认可，而不只是义务。

**为什么**
这是平均分最爱掩盖、也最能让整盘水位被拽下来的一维。流程到了 L4、激励还在 L1，员工就是不配合，照样卡死。

**过关线**
激励与晋升机制中，AI 重构/资产贡献被正式纳入；有一条明确的"节省时间再投入"规则。

> 💡 **人不因为"更有效率"而采纳新技术。**
> 真实的采纳机制是社会性的：
> - 身边某个**跟自己相似**的人用了，并且拿到了正面结果（更被认可、更轻松、更受重视）
> - 或者，感觉周围人都在用了，不用会掉队
>
> **所以"多讲一遍 ROI"几乎没有用，"让人看见同类在用并且获益"才有用。**
>
> 两个可操作的推论：
> 1. **可见的地位反馈 > 工具手册。** 让用得好的人在高层面前被点名、在晋升材料里有位置——这比再办一轮培训有效得多。
> 2. **让干活过程可见。** 最好的 AI 培训不是一门课，而是让大家**看着 agent 干活**——包括看它翻车、看你怎么调整、看它最后做对。观摩现场放在哪，由你的工作基质决定（见第 0 步）。
>
> ⚠️ 但注意边界：是把 AI **接进**考核逻辑，不是**强制**考核 AI 使用率。指标一旦考核动作数量，就一定会被做成表演。**考核 AI 带来的结果，不考核 AI 的使用次数。**

## ⑥ 治理 — 先装刹车，再给自主权

**要解决的卡点：** 不敢全面铺开——权限乱、出错无兜底、换个人就跑不起来；或者反过来，agent 已经在自主行动，但没人说得清它归谁管（治理维度）。

**做什么**
- 把权限、错误兜底、可观测、可交接做成框架。
- 让流程"换个人也能接着跑"，而不是绑在某个高手身上。
- 给每个 agent 配齐**六件控制**（下表），再逐步放权。
- 跑一遍下面的**致命三要素**清单和**三项韧性压力测试**。

**为什么**
BCG 2026 年的调研里，相当多公司预期几年内让 agent 不经人工审批就自主决策，但目前具备整套控制能力的只有约二十分之一；而控制做得好的公司，从 agent 身上拿到的价值显著更高。**自主权要用控制能力去换。**

**过关线**
关键流程权限清晰、有兜底和负责人，可审计、可交接；每个在跑的 agent 都有 owner 和运行日志。

---

### 每个 agent 的六件控制

| 控制 | 一句话自检 |
|---|---|
| **归属（Owner）** | 这个 agent 出了事，找谁？——跨部门的 agent 尤其要写清楚 |
| **可观测** | 它刚才做了什么、为什么这么做，能不能查到？ |
| **审批与回滚闸门** | 哪些动作必须人点确认？做错了能不能撤回？ |
| **权限最小化** | 它能碰到的数据和系统，是不是刚好够用？ |
| **审计日志** | 一份只追加、不修改的运行记录，独立于 agent 本身存在 |
| **成本护栏** | token/调用费用有没有上限和监控？谁在看账单？ |

> 成本这一条常被忽略。麦肯锡 2026 年的调研里，约五分之一的受访者说运营成本（包括 token 成本）已经在约束他们的 AI 使用。成本失控，最后的结局往往是"一刀切停用"。

### Agent 安全清单：致命三要素

一个 agent 同时具备下面三条时处于高危状态：

1. 能访问**私密数据**（内部库、档案、客户信息）
2. 能读取**不可信内容**（外部网页、投递的文件、外来邮件）
3. 能**对外发送**（发邮件、调外部接口、访问外网）

**三条齐备，攻击路径就成立**：攻击者把恶意指令藏在 agent 会读到的内容里——这叫间接注入，攻击者从头到尾没跟你的 agent 说过一句话——agent 分不清"用户的指令"和"读到的内容"，照做，数据外流。

**用法：** 把在跑的每个 agent 拉张表逐个过一遍。
- 三条全占 → 高危。砍掉一条（最容易砍第 3 条：只写草稿，由人点发送），或加人工复核
- 只占两条 → 风险可控

这张表的价值在于：它把"AI 安全"从一个虚的话题，变成一张任何人都能填的表。

### 三项韧性压力测试

大多数成熟度框架只测"你用了多少 AI"，不测"你的 AI 扛不扛得住事"。而后者恰恰是中国企业和西方企业处境最不同的地方——供应商可能退出市场、模型可能被限制、工具链可能被要求替换。

问自己三个问题，答不上来就是治理维度的真实短板：

**测试 1 · 换模型能不能活？**
底层模型换一家，你的流程要重做多少？如果 prompt 里写死了大量针对某个模型缺陷的补偿逻辑，换模型就等于重建。
> agent 循环里写死的假设，会随着模型变强而过期。今天的补丁是明天的负担。**别为当前模型的缺陷做太重的工程投入。**

**测试 2 · 供应商退出怎么办？**
你依赖的平台如果明天停止对你所在市场的服务，你的数据拿得出来吗？把每一个外部依赖当作**可被单方面撤销的访问权**，而不是稳定的基础设施。
> 分层看风险：支付层 > 身份认证层 > 协作通讯层 > 数据库层 > 模型层。越靠上，被切断时越致命。优先给最致命的那层准备备份通道，并且**在主通道还能用的时候就验证过备份**——而不是等出事再试。

**测试 3 · 单点故障能不能恢复？**
链路中某一环挂掉，能从断点续跑，还是必须从头重来？
> 关键是**把状态外置**：一份只追加、不修改的流程事件日志（每一步的输入、AI 输出、人的动作、改了什么），独立于任何单个 agent 存在。这份日志同时给你三样东西——断点恢复能力、完整审计轨迹、以及改进方向（人反复改同一个地方，那就是该改 agent 的地方）。模板见 [`honest-metrics.md`](./honest-metrics.md)。

## 怎么判断"做到了 AI 原生雏形"

不是做到 L5，而是：**装好引擎 + 一个被证明的战果 + 比起点涨了至少一级。**

先在启动时跑一次自测，存下 **T0 基线**。之后看三条：
- 引擎转起来了（一号位示范 + 专职小队 + 全员参与）；
- ≥1 条 AI 重设计流程在真实业务跑、有 before/after 数字和 HITL 率曲线；
- 相比 T0 基线，核心维度至少上升 1 级（**按过了证据闸门的分数算**）。

> ⚠️ 永远别把成功定义成"做到 L5"，否则就是个永远做不完、永远能被说"还没到位"的无底洞。
> 拿去汇报的，是"我们从 X 走到了 Y"的故事，不是一张光秃秃的诊断表。
