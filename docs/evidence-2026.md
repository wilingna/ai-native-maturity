# 附录：设计依据与出处

> 模型本身不依赖这页也能用。这里只是把"为什么这样设计"对应到公开研究上，方便需要查证的人回溯。
> 内容为对公开报告的概括转述，数字以原报告为准。

| 模型里的设计 | 依据（一句话） | 出处 |
|---|---|---|
| **最短板定级**，不取平均 | AI 已进入近九成企业，但真正拿到显著财务回报的始终是一小撮——多数组织不是整体差，而是卡在某一处 | [1] [2] |
| **流程**：重新设计，而不是贴在旧流程上 | 拿到真回报的公司，绝大多数从根上重设了工作流；其他公司约四分之一 | [1] |
| **流程**：按任务选人机协作方式 | 问答 / 探索 / 委派 / 协作，按任务选，不追求自主度最大化 | [3] |
| **方向**：收拢资源、价值进 P&L | 最成熟的公司集中投入少数高价值流程，并用 P&L 或业务 KPI 衡量 AI | [2] |
| **方向**：一号位当众使用 | 经理可见地使用 AI，团队的信任与价值感知明显更高 | [3] |
| **人才**：写 spec、返工税 | AI 省下的时间里接近四成被返工吃掉 | [4] |
| **人才**：人机编制规划 | 成熟公司更普遍在做"agent 时代哪些岗位该存在"的规划 | [2] |
| **激励**：奖励不稳的尝试、管好节省的时间 | 组织因素对 AI 成效的影响约是个人因素的两倍；节省的时间常被直接变成加活 | [3] [4] |
| **治理**：先装刹车，再给自主权 | 很多公司计划让 agent 自主决策，但配齐控制的极少；控制好的公司拿到更多价值 | [2] |
| **治理**：成本护栏 | 约五分之一的企业表示 token 等运营成本已在约束 AI 使用 | [1] |
| **证据闸门**、按团队分别测 | 成熟度应测"正在发生的事"，并按团队/部门分布看，而非一个混合分 | [5] |
| **第 0 问 · 工作基质** | 本模型原创：主流框架默认协作发生在 IM 里，这在大量中国大型组织不成立 | — |
| **三项韧性测试** | 本模型原创：换模型 / 换供应商 / 单点故障，针对国内企业的处境 | — |
